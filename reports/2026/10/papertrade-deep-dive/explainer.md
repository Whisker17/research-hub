结论先行：Papertrade 是一个以 Hyperliquid 盘口中间价作价、以协议 LP 做对手方的合成永续。它只从赢家的盈利里收费，并把 PAPER 只铸给亏损者（[F1](#F1)、[F2](#F2)）。“零资金启动”中的排队信用实际只用了 $22.86。LP 65 分钟就到了 $5M，之后被质押者分红上限压在约 $5M（[F3](#F3)）。上线后的热度是典型的上线脉冲；质押者分到的 USDC 约等于交易者净亏的 80%，相当于亏损者拿回了现金（[F5](#F5)）。

操纵事件的直接原因是上线时链上 OI cap 约每侧 $100B，而不是文档写的“当前 OI + $1B”（[F7](#F7)）。对 Mantle 来说，账本、队列、铸币都能原样移植。链级缺口只有两项：同链可读的原生价格，以及原生 USDC / CCTP。真正的约束是需求（[F11](#F11)、[F12](#F12)）。

## F 结论 {sheet span=4}

```prereq B-0 l1 3min
# HyperCore 与读预编译
是什么: [[HyperCore]] 是 Hyperliquid 运行订单簿的共识层。[[HyperEVM]] 合约可以 staticcall 固定地址的[[预编译]]，读到“EVM 区块构建时最新的 HyperCore 状态”[5]。
为什么需要: Papertrade 的价格就是这样读进合约的，不经过链下签名者。
例子: `0x…080e` 输入资产编号（BTC = 0），返回 `(uint64 bid, uint64 ask)`。一次读取约 8,240 gas [5][8]。
误解: 误解：预编译读到的是连续实时价格。事实：每个 EVM 区块读一次快照，小块每 1 秒一个 [6]。
深入: [5] Read precompiles 一节
```

```prereq B-1 l1 3min
# vault 对手方的合成永续
是什么: [[合成永续]]不撮合买卖双方。协议记下入场价，平仓时按新价格结算盈亏，[[vault 对手方]]直接赔付或收钱 [1]。
为什么需要: “零滑点、无 spread”来自这种结构。协议不需要真的在别处开仓。
例子: Alice 的 $100,000 名义仓位，只是 LP 对价格变化的一项支付承诺。
误解: 误解：没有在外部开仓，所以没有 funding。事实：GMX v2、gTrade 也不在外部开仓，照样收 funding [14][17]。
深入: [1]《Trades and pricing》
```

```prereq B-2 l1 3min
# BBO、mid 与 mark
是什么: [[BBO]] 是买一和卖一。[[mid]] 是两者的中点，中点上通常没有可成交的挂单。[[mark price]] 是 Hyperliquid 自己做清算用的价格，取三项的中位数 [7]。
为什么需要: Papertrade 用 mid 开仓、平仓和清算，而 Hyperliquid 自己不用 mid 清算。
例子: 10-12 的 BTC 盘口是 $82,513.0 / $82,514.0，mid = $82,513.5，价差 1 tick ≈ 0.12 bps [3]。
误解: 误解：共识验证过的价格就是公允价格。事实：共识只证明“这是当时的盘口”[1]。
深入: [7] `Robust price indices` 页
```

```prereq B-3 l1 4min
# Martingaler 队列
是什么: [[payout queue]] 是一个先进先出的欠款队列。LP 付不出的盈利先排队，等后面的亏损进来再按顺序付 [2]。
为什么需要: 这是 Papertrade 声称“零资金启动”的依据。
例子: 开盘第 1 个 6 秒内，3 个赢家各赢 $7.62，LP 为 0，所以排队。下一笔亏损进来后，一个区块内全部付清 [3]。
误解: 误解：队列保证最终偿付。事实：白皮书只有两个概率游戏的模拟，没有证明最终偿付 [2]。
深入: [2] §2.2–2.3
```

```prereq B-5 3min
是什么: [[OI cap]] 限制每侧新开仓的总量。净敞口 = 多头名义 − 空头名义，它决定 LP 的方向性风险。
```

## K 机制二：成本只从赢家收取 {depth=2}
Papertrade 不收开仓费、价差和 funding。成本分三步，只在盈利平仓时扣：
1. 0.2 bps [[死区]]：盈利按“出场价差 0.2 bps”计算。
2. [[asymmetric impact]]：按价格变动幅度缩放盈利，变动越小，扣得越多。
3. 2% win fee：从缩放后的盈利里扣。

```solidity title="摘自 Papertrade Docs《Asymmetric impact PnL》（链上参数）"
adjustedPnl = rawPnl * scale
scale = (1 - baseRate) / (1 + term1 + term2)      // baseRate = 0.1
term1 = 1 / (move * rateMultiplier)               // rateMultiplier = 15000
term2 = referenceNotional / (1e6 * move * positionMultiplier)
// referenceNotional = $100,000；positionMultiplier：BTC 814.598，ETH 483.979
```

## N 为什么在 HyperEVM：HyperCore 提供了什么 {depth=2}

## V 术语表 {depth=2}
```glossary
HyperCore | Hyperliquid L1 | 运行 Hyperliquid 现货与永续订单簿的共识层。 | 不是 HyperEVM
HyperEVM | | 与 HyperCore 同一共识的 EVM 执行层，合约可读 HyperCore 状态。 | 不是独立 L2
预编译 | precompile | 固定地址的系统合约，合约用 staticcall 读取链级状态。 | 不是普通合约
BBO | best bid / offer | 订单簿的买一价和卖一价。 | 不是成交价
mid | 中间价 | 买一和卖一的平均值，通常没有挂单。 | 不是 mark price
mark price | 标记价格 | Hyperliquid 清算用的价格：三项价格的中位数。 | 不是 mid
合成永续 | synthetic perp | 协议只记账、按价格结算，不撮合真实对手。 | 不是订单簿永续
vault 对手方 | 金库对手方 | 协议资金池承担所有交易者的另一边。 | 不是做市 vault
hard bust | 硬清算 | 越过 bust 价就没收全部保证金，不按剩余权益结算。 | 不是部分清算
死区 | deadband | 盈利按出场价差 0.2 bps 计算，更小的盈利归零。 |
asymmetric impact | 非对称 impact | 只缩放盈利的系数，价格变动越小扣得越多。 | 不是滑点
三桶账本 | three-bucket | LP cash、sideBucket、payout queue 三个记账桶。 |
payout queue | 付款队列 | LP 付不出的盈利按先进先出排队等待偿付。 | 不是提现队列
sideBucket | | 队列非空时，亏损先放进这里，专门偿还队列。 |
OI cap | 持仓上限 | 每侧新开仓总量的上限，由 market keeper 调整。 | 不是亏损上限
relayer | 中继 | 官方运营的地址，唯一能把开平仓意图提交上链。 | 不是 4337 bundler
session key | 会话密钥 | 用户授权的临时密钥，只能开平仓，不能提现。 |
签名报告 | signed report | 链下节点签名的价格，交易带入后由合约验证。 | 不是推送喂价
```
