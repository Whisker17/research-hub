结论先行：链的性能不是一个数。吞吐、延迟、尾延迟、状态新鲜度和持续能力分别受不同组件约束（F1）。L1 的上限来自“最慢的合格验证者能否及时重放”和投票轮次；L2 的实时路径可以很快，但持续能力受执行、DA 和证明三者中最小的一个限制（F2）。

B-1

五个性能指标

~3min
是什么

吞吐是单位时间完成的工作量；延迟是一笔交易从提交到可依赖的时间；尾延迟看 p99；状态新鲜度是读到的状态落后多少；持续能力是长期不积压的上限。

为什么这里需要

每个组件限制的指标不同。并行执行提高吞吐，预确认改善延迟，DA 和证明决定持续能力。

最小例子

Mantle 压测：饱和吞吐 29.5M gas/s，链固有延迟 2 s，端到端 18.2 s。

常见误解

误解：TPS 高，体验就好。事实：Mantle 压测里延迟增量全部来自排队，不来自链。

[24] Mantle 内部压测报告 §3

B-2

L2 的两条路径与三个 head

~4min
是什么

实时路径：sequencer 排序执行，产出 unsafe 区块。安全路径：batcher 把数据发到 L1，节点从 L1 派生出 safe 区块，L1 最终后变成 finalized。

为什么这里需要

L2 可以让实时路径不等安全路径。但安全路径长期落后时，积压会越来越大。

最小例子

OP Mainnet：unsafe 约 2 s，safe 数分钟，finalized 约 15–30 分钟。

常见误解

误解：7 天是最终性。事实：7 天是标准桥提现延迟，挑战不会重组 L2 链。

B-3

关键路径与流水线

~3min
是什么

关键路径是一项工作必须依次完成的步骤。流水线让不同区块的不同阶段重叠执行。

为什么这里需要

流水线提高稳态吞吐，但不缩短单块的端到端时间。理解这一点才能区分“更快”和“更多”。

最小例子

并行执行时间 T ≥ max(W/p, L)：W 是总工作，p 是线程数，L 是最长依赖链。

常见误解

误解：加线程就能无限加速。事实：依赖链 L 不随线程数缩短。

B-4

state root 与 merkleization

~3min
是什么

state root 是全部状态的一个哈希承诺。每次出块都要把改动写进 Merkle Patricia Trie（MPT），重算到根，这一步叫 merkleization。

为什么这里需要

出块和验证都要等 root。2024 年 root 占 reth 封块时间超过 75%，2026 年已流水线化。

常见误解

误解：root 永远是瓶颈。事实：Reth 2.0 把区块末尾的 root 降到 1–2 ms。

B-5

预确认（preconfirmation）

~3min
是什么

sequencer 在完整区块封好之前，先流式发布部分交易的顺序或执行结果。

为什么这里需要

它决定用户多快看到结果。Mantle 当前没有亚秒预确认，下限就是 2 s 出块间隔。

常见误解

误解：预确认就是最终性。事实：它承载的是 sequencer 的信任假设，可以被撤回。

B-6

DA 与 blob

~3min
是什么

数据可用性（DA）保证别人能取到重建或验证所需的数据。L2 把交易批次压缩后放进 Ethereum blob 发布。

为什么这里需要

执行再快，数据发不出去也会积压。blob 容量由所有 L2 共享。

最小例子

每个 blob 装 130,044 字节；当前每块 target 14 个 blob。

常见误解

误解：状态根很小，所以要发布的数据也很小。事实：root 不能代替数据本身。

F1

性能不是一个数：五个指标分别受不同组件约束

置信度: high
论断

流水线提高稳态吞吐，但不缩短单块延迟。预确认提前给出反馈，但不加快最终性。并行执行只能利用已经存在的独立工作。读路径的响应快，不等于状态新鲜。

证据

inferred 由 work/span 下界、RISE shreds 与 OP Subblocks 的语义、Block-STM 的顺序等价约束推出（台账 S8、B7、B17、E11、R14）。inferred 读路径的取舍（B65）。

影响

评估任何优化之前，先写清它改的是哪个指标、哪一层。

F2

L1 与 L2 的上限来自不同地方

置信度: high
论断

L1 的每个验证者都要重放全部区块，所以容量受“最慢的合格验证者能否及时重放与追赶”限制；正常路径的通信轮次有理论下界。L2 的实时路径可以很快，但持续能力受执行、DA 发布与证明三者中最小的一个限制。

证据

observed Solana 提到 100M CU 前要求超过 70% 质押启用 XDP，并写明大区块拖慢重放（S16、S59）；n ≥ 5f−1 才能两步达成拜占庭共识（S21）。observed OP Stack 中未在 12 小时 sequencing window 内发布的数据会被丢弃（S5）。inferred S60。

影响

L2 的“高性能”必须连同 DA 和证明的余量一起验收，不能只看 sequencer 执行了多少交易。

K

组件 ①：账户、交易表达与准入

会产生什么问题（Alice 的买单）：

  • 一个业务动作被拆成多个协议动作：准备 gas、approve、兑换、购买。每一步都要签名和等待。
  • 准入的成本先于收费：无效交易在被拒绝前，已经消耗了解析、验签和模拟。
  • nonce 队头阻塞：同一账户的前一笔卡住，后面无关的操作也要等。

峰值时先坏的是入口，不是执行

置信度: high
论断

Mantle 压测在饱和时，端到端延迟从 3.4 s 涨到 18.2 s，增量全部来自自排队与 mempool 积压；写入端 HTTP 429 率 7.9%（优化前 67%）；多 bot 争抢同一 borrower 造成 27–49% 的 guard revert。

L

组件 ②：网络传播

会产生什么问题：

  • leader 的上行扇出：把同一个区块发给 N 个节点，带宽随 N 增长。
  • 传播跳数：每一跳至少一个单程网络时延。Anza 认为传播延迟主要由网络时延决定，不由传输或计算决定。
  • L2 的对应问题不是全网投票，而是 sequencer 向跟随节点、RPC 和应用的分发。

M

组件 ③：排序、共识、出块与预确认

这一层有三件事：排序决定先后，出块决定选哪些交易和何时封块，共识让多方接受同一条链。L1 三件都做；单 sequencer 的 L2 主要做前两件。

F5

共识轮次有下界，“更快”要用假设换

置信度: high
论断

部分同步拜占庭共识要在 2 个消息延迟内决定，需要 n ≥ 5f−1；PBFT 类需要 3 个。Alpenglow 的约 150 ms 是仿真中位数，不含计算开销，容错是“20% 恶意 + 20% 离线”。MonadBFT 当前 300 ms 出块、600 ms 最终。

证据

observed PODC'21 论文（S21）；solana.com Alpenglow 页与 Anza 博客（S22–S25）；Monad Docs（S29–S31）。inferred 主网实测尚未公开（S26）。

影响

比较“最终性”数字前，先确认它是仿真、自测还是主网实测。

F6

执行与共识解耦：换来执行预算，代价是用户可见的语义

置信度: medium
论断

Monad 的共识只对顺序达成一致，提案带 D=3 块前的状态根；共识只看得到旧状态，所以引入 10 MON 的 reserve balance。Ethereum Glamsterdam 采用 ePBS（EIP-7732），延迟执行（EIP-7886）处于 Stagnant。

证据

observed Monad Docs（S41–S43）；EIP-7732 / 7886 / 7773（S45–S47）。inferred 代价包括 root 滞后、准入规则改变、分歧发现更晚（S58）。

影响

L2 的 sequencer 本来就不需要投票，这条路线对 Mantle 的参考价值主要在“延迟 merkleization”，见 O。

F7

L2 出块的尾延迟来自 state root 与存储 IO

置信度: high
论断

OP Stack 出块是“准备 attributes → 执行 → getPayload 封块（算 root）→ gossip”的串行环。Base 主网上每个 Flashblock 算一次 root 约 130 ms；把 root 移到最终区块后，构建 P50 从 150 ms 降到 10 ms。Base 自测 Geth 构建 p99 为 2,319 ms，Reth 为 698 ms。

证据

observed OP Spec exec-engine（B1）；Base 博客（B2–B4）；OP Mainnet 换 NVMe 前区块会退化到 2.5–3 s（B5）。inferred B8。

影响

Mantle 的 eager next-block construction 缩短的是块间空窗。下一步收益在 root 与 IO，而不在解释器。

F8

预确认在 2026 年收回到协议内或自研栈，信任假设没有变

置信度: high
论断

Base 计划在 Denim 中废弃 Flashblocks，改为每 200 ms 一个带独立 state root 的 canonical 区块。OP Labs 用自研 Subblocks 取代 Flashblocks，并在迁移完成后停止运行 op-rbuilder。OP 文档写明 subblock 预确认可以在 sequencer 能 reorg unsafe 区块的同等条件下被撤回。MegaETH 由 sequencer 签名每个 mini-block 头，签名不代表最终性。

N

组件 ④：执行（调度与 VM）

执行层有三类瓶颈，处理方法不同：

  • 计算：解释器分派、预编译、keccak。可以用解释器优化或 JIT 压缩。
  • 等待状态：冷读 SSD，以及 trie 带来的读放大。可以用预取、缓存、更好的存储压缩。
  • 业务串行依赖：多笔交易改同一个池子。只能改业务或状态布局。
F9

2026 年 reth 类客户端的剩余瓶颈是冷读，不是解释器

置信度: high
论断

Base 测得存储访问多的区块执行时间约为无存储访问区块的 30 倍。evm2 的解释器优化在主网回放中只快 4.8–6.2%。revmc JIT 在合成负载上快 1.85–19 倍，在 L1 历史同步上只快 1–10%。

证据

observed Base 博客（E3、E4）；revm-vs-evm2 台账 H37（E8）；Paradigm revmc 博客（E32）。inferred E9、E38。

影响

JIT 只对计算密集的合约有意义。Mantle 应先用 profile 测出计算占比，再决定是否立项（R12）。

F10

真实负载的可并行度不高；并行方案分三类

置信度: high
论断

声明式（Solana 账户锁、Sui 对象所有权）、乐观式（Block-STM、Monad、Sei Giga Ares）、辅助验证式（EIP-7928 BAL）。以太坊近期区块的中位并行度小于 2；RISE pevm 在内存态主网回放中平均快约 2.02 倍。reth 与 geth 都已实现 BAL 路径，但 Glamsterdam 未上主网，所以主网尚未生效。

证据

observed Block-STM 论文与各链文档（E11–E15）；MegaETH 研究页与 pevm benches（E18、E19）；EIP-7928、reth v2.8.0、geth v1.17.9（E20、E22、E28、E29）。inferred E31。

影响

Mantle 2025 年的 49.1% “依赖率”是启发式口径（同发送方、同合约同 selector），不能当作并行收益上限。先测 slot 级读写集（M43、M45）。

O

组件 ⑤：状态访问、承诺与持久化

一笔写入要经过四件事：读到旧值、在执行中维护可回滚的修改、更新 trie 并重算 root、按批次持久化。四件事的瓶颈各不相同。

F11

state root 已不再是 reth 的关键路径瓶颈；“移出关键路径”成为共同做法

置信度: high
论断

Reth 2.0 用跨块保留的 sparse trie 缓存，把主网区块末尾的 root 降到 1–2 ms；Paradigm 因此重启 revmc，并计划基于 BAL 做完整并行。Monad 延迟 D=3 块的 root，RISE shreds 不在预确认路径上算 root，Sei Giga 用 LtHash 写日志摘要。以太坊的 EIP-7862（延迟 state root）在 Hegotá 评级中被暂缓。

证据

observed Paradigm 博客与 reth v2.0.0 release（E5、E7、E51）；Monad Docs（E49）；RISE 博客（B7）；Sei Docs（E55）；EF Hegotá 文（E54）。inferred E56。

影响

F12

存储：KV 上再存一棵 trie 造成读放大；新结构的数字多为作者自测

置信度: medium
论断

base/triedb 估计在通用 KV 上存 MPT，读写一个值约 50 次磁盘操作，按页组织可降到约 4–8 次。MonadDb 原生实现 Patricia trie 并用 io_uring；MIP-8 把存储承诺改成 4 KiB 一页。Reth Storage v2 把 Gigagas 级区块的持久化从 8.4 s 降到 0.4 s。QMDB 自称比 RocksDB 快 6 倍，NOMT 已发布 1.0.x。

证据

影响

F13

状态增长让“全部放进内存”不再是免费午餐

置信度: medium
论断

2026-01 geth 状态库约 390 GiB；gas 上限从 30M 提到 60M 后，状态年增约 116 GiB。所有执行客户端自 2025-07 起支持删除 merge 前历史（省 300–500 GB），完整滚动历史过期与 state expiry 仍在研究。MegaETH 2024 年“状态可全部放进内存”的前提是约 100 GB。

证据

observed EIP-8037（E61）；EF 博客（E57–E59）；MegaETH 研究页（E64、E67）。inferred E69。

影响

内存化只能解决读延迟，不能消除 root、持久化、DA 与证明的成本。

P

组件 ⑥⑦：数据可用性、证明与结算

这两层决定持续能力：sequencer 执行得再快，数据发不出去或证明跟不上，积压就会持续变大。

F14

blob 共享容量约 152 KB/s，小额交易先受 DA 约束

置信度: high
论断

OP Stack 一个 blob 装 130,044 字节；BPO2 之后每块 blob target / max 为 14 / 21，即约 152 / 228 KB/s，由所有 L2 共享。按每笔 100 字节算，约支撑 1,500 / 2,300 TPS。Mantle 的 60M gas / 2 s 区块若装满 21k gas 转账，约需 143 KB/s。EigenDA V2 自称 100 MB/s，但安全假设是 restaking 法定人数。

证据

observed OP Spec（B30）；EF Fusaka 公告（B31）；EigenDA 博客（B37）。inferred B33、B34、R8；B39。

影响

Mantle 单靠提高 gas 上限扩不了小额交易的容量。容量规划要同时看压缩率与 blob 价格。

F15

证明能力是持续上限；主流做法是 TEE / optimistic + 按需 ZK

置信度: medium
论断

Base 写道 optimistic 系统下“不能产生比证明系统能证明的更多数据”。Base Azul 采用 TEE + ZK 多证明：两种一致时 1 天结算。BOB 的 Kailua 默认 optimistic，争议时只证明 6 个区块。Axiom 自测用 4 张 5090 证明 L1 区块，p99 为 9.7 s。

影响

F16

响应快不等于状态新鲜

置信度: medium
论断

MegaETH 的 replica 节点直接应用 sequencer 的执行结果，不重新执行；full 节点独立重执行。在 Base 的 Flashblocks-aware RPC 上，eth_call pending 返回的区块上下文可能落后约 5 块。但返回的状态已包含全部收到的 Flashblocks。OP Subblocks 要求 RPC 节点自己执行交易得出状态。

术语表

sequencer排序器
L2 上负责接收交易、排序、执行并产出区块的节点。不是验证者集合
派生derivation
节点只用 L1 上的数据，确定性地重建 L2 区块的过程。不是从 sequencer 同步
unsafe 区块unsafe head
sequencer 已产出、但还不能从 L1 数据派生的区块。不是无效区块
预确认preconfirmation
在完整区块封好前，sequencer 先发布部分交易的顺序或结果。不是最终性
state root状态根
全部状态的一个哈希承诺，每个区块都要重算。不是区块哈希
merkleizationMerkle 化
把状态改动写进 trie 并重算到根。不是持久化
关键路径critical path
一项工作必须依次完成的步骤链。不是最耗资源的步骤
流水线pipelining
让不同区块的不同阶段重叠执行，提高稳态吞吐。不缩短单块延迟
持续能力sustained capacity
长期运行而不积压的上限，受执行、DA、证明中最小者限制。不是峰值 TPS
状态新鲜度freshness
读到的状态落后最新执行结果多少。不是 RPC 响应时间
DA数据可用性
保证参与者能取到验证或重建所需的数据。不是网络传播
blobEIP-4844 blob
Ethereum 区块附带的大块数据，L2 用它发布批次。不是 calldata
BPOblob parameter only fork
只调整 blob target / max 的小型分叉。
eager next-block construction提前构建下一块
封完上一块后立即开始构建下一块，缩短块间空窗。不是预确认
BALBlock-Level Access List，EIP-7928
区块携带每笔交易读写了哪些状态，验证端据此并行。不是调度器
Block-STM乐观并行执行
先并行执行，再按预定顺序验证读集，冲突时重执行。结果等同串行
reserve balance储备余额
Monad 让共识在只看得到旧状态时仍能安全纳入交易的规则。
ePBSEIP-7732
把执行 payload 的验证移出共识关键路径的提议者–构建者分离。不是延迟执行
JIT即时编译
运行时把热点合约字节码编译成机器码。不改 gas 语义
冷读cold read
读取不在内存缓存里的状态，要访问 SSD。
sparse trie稀疏 trie
只加载被改动路径的 trie 片段，用于后台计算 root。
SystemConfigL1 配置合约
L1 上的合约，参数经派生带到 L2，例如 gas target 与 min base fee。改它不需要硬分叉
DA footprintJovian DA 计量
按估算的 DA 字节计入区块的 blobGasUsed，参与 base fee 更新。不是 L1 data fee
konaOP Stack Rust 实现
Mantle 的 SP1 证明程序由它编译，在 zkVM 里重做派生与执行。
vkey验证密钥
L1 合约用它验证 SP1 证明；证明程序一变就要轮换。
2D nonce二维 nonce
一个账户有多条独立的 nonce 序列，避免队头阻塞。不解除状态冲突
native AA原生账户抽象
在协议层支持智能账户、代付和会话密钥。不是 ERC-4337
replica 节点replica node
直接应用 sequencer 的执行结果、不重新执行的读节点。不是 full 节点
