背景动机

问题：agent 要参与链上经济，就要能签名和付钱。直接把私钥交给 agent 风险太大；每笔都让人确认，agent 又失去价值。

各家 agent 钱包都在回答“给多少权力、放在哪一层约束”。

为什么现在：

  • 2026 年 2 月到 8 月，Coinbase、OKX、Binance、MetaMask 相继推出 agent 钱包（见 E）[7][15][16][20]。
  • 你给的 MetaMask 推文约发于 2026-10-14，内容是 Agent Wallet 接入某个 bot，不是上线公告 [7]。
  • BNB Chain 把钱包、部署、支付、身份整合进 Agent Studio，v2 起 agent 可以收款 [23]。

范围：核心四家的产品形态、技术原理与边界；扩展生态按统一维度对比；钱包周边协议；活动场景；Mantle 启示。

非目标：真实资金测试与安全审计；投资建议；协议规范的逐字段细节。

贯穿全文的例子（示例，非真实产品配置）：一个研究 agent 每天用不超过 10 USDC 购买付费数据 API，按 x402 按次付款。后面每个面板都先看这笔钱在各家产品里怎么走。

B-0

可信执行环境（TEE）

~5min
是什么

CPU 里一块隔离的执行区。密钥在里面生成和使用，宿主系统和运维人员读不到。

为什么这里需要

MetaMask server-wallet、Coinbase、OKX、Phantom 都把 agent 钱包的密钥放在 TEE 里。agent 只拿到“请求签名”的凭证。

最小例子
agent → 钱包服务：sign(tx)
TEE：检查策略 → 用内部密钥签名 → 返回签名
agent 全程拿不到私钥
常见误解

误解：密钥在 TEE 里，agent 就安全。事实：TEE 只保护密钥。agent 能请求什么签名，取决于策略。

门限签名（MPC）

~l2
是什么

私钥被拆成几份，分在不同机器上。签名时各方协作计算，任何一处都不会拼出完整私钥。

为什么这里需要

Binance Agentic Wallet 用 MPC keyless 架构；规则在 Binance API 层执行。

B-2

智能账户与 session key（smart account / session key）

~8min
是什么

智能账户是合约账户，签名校验规则写在合约里。session key 是主人签发的临时密钥，可以被限定在指定的合约、函数、额度和有效期内。越界的调用在链上回滚。

为什么这里需要

只有这条路线能做到“策略在链上、厂商下线也有效”。EIP-7702 让 EOA 委托给合约代码；ERC-4337 提供 paymaster 代付 gas。

最小例子
session = { calls: [Router.swap], spend: 100 USDC/天, expiry: 30 天 }
agent 调用 Vault.withdraw → 验证失败 → 回滚
常见误解

误解：用了 session key 就安全。事实：Altana 不配 calls 时，session 在额度内可以调用任意合约。

B-3

签名授权：Permit2 与 EIP-3009

~6min
是什么

不发交易，只签一条链下消息，就把花钱的权力交给别人。Permit2 授权第三方从你的地址转走代币；EIP-3009 授权一笔指定金额的转账，在有效期内任何人都能提交。

为什么这里需要

很多钱包只按已发交易统计额度，不统计签出去的授权。MetaMask 的额度就不计 Permit2 签名 [3]。

最小例子
3009 授权：from, to, value, validAfter, validBefore, nonce
暂停 agent 之后，窗口内这条授权仍可被提交
失效办法：cancelAuthorization，或等过期
常见误解

误解：撤销 agent 的权限，已签的授权就失效。事实：链下签名只能在链上 cancel 或等过期。

B-4

x402（HTTP 402 按请求付款）

~6min
是什么

服务端返回 HTTP 402 和报价；客户端签一条付款授权，带着它重发请求。facilitator 负责验签和上链结算，不托管资金。

为什么这里需要

agent 购买数据和 API 主要走这条路。默认流程先验签、后结算：服务端先提供资源，再扣款 [34]。

最小例子
GET /data → 402 { price: 0.01 USDC, payTo, network }
签 EIP-3009 授权 → 重发 GET + PAYMENT 头
→ 200 数据；facilitator 随后上链结算
常见误解

误解：x402 总是先付款后交付。事实：默认的 authorization 流程在服务端运行之后才结算。

MCP 与 skill

~l2
是什么

MCP 是 agent 调用外部工具的协议。skill 是一组写给 agent 的说明和脚本，告诉它何时调用哪个命令、调用前要做什么。

为什么这里需要

多数 agent 钱包靠 skill 安装 CLI。很多“每笔先确认”的规则只写在 skill 里，由 agent 自己遵守。

核心四家逐家拆解

形态与确认：

产品 入口 默认确认 退出
MetaMask mm CLI + skills skill 要求逐笔确认；越界才 2FA 说法矛盾（见下）
Coinbase CLI awal / MCP x402 自动付款，上限在 UI 设 邮箱恢复；导出未写明
Binance skills + baw CLI 授权后不逐笔确认；风险分 ≥4 推 App 私钥不能导出
OKX skills + onchainos CLI 后端 confirming，确认后 --force 可导出助记词，之后 agent 失效

能力与边界：

产品 能力 已知边界
MetaMask 转账、swap / bridge、Hyperliquid perps、Polymarket、earn、x402 Permit2 签名不计额度；多跳重复计数；Beast 无白名单
Coinbase CLI：USDC 转账、Base 上交易、x402；MCP：只有 x402 限额执行层未公开
Binance swap、转账（只到白名单地址）、限价、预测市场、DeFi、x402 不支持 EIP-191，SIWE 登录做不了；四类额度无总上限
OKX 转账、swap、跨链、任意 calldata、personalSign、x402 策略只有金额与转账白名单

MetaMask Agent Wallet：

  • 两种密钥模式。server-wallet 的密钥在服务端 TEE；BYOK 把助记词放在环境变量里，本地签名 [1]。
  • Guard Mode 有威胁扫描、网络 / 地址 / 收款方白名单和滚动 24 小时额度；Beast Mode 只有威胁扫描。切到 Beast 要 2FA [2]。
  • 原生币不足时，ERC-20 转账和 swap 自动走 EIP-7702 relay，手续费从所转代币里扣；在支持的链上用 ERC-7821 把 approve 和交易合成一笔 [1]。
  • x402 由 skill 里的脚本完成，只支持 exact + EIP-3009。脚本无状态，重跑就会再扣一笔 [6]。
  • 导出：8 月 GA 博文说可随时导出助记词，10 月 8 日的指南说 server-wallet 目前不能导出 [7][8]。
  • Advanced Permissions 是另一个产品：dapp 通过 ERC-7715 向 MetaMask 扩展请求权限，session account 按 ERC-7710 赎回，由链上 caveat enforcer 执行 [9]。

Coinbase / Base：有三条路径。

  • Agentic Wallet（独立预算钱包）：CLI 能转 USDC、在 Base 上交易、付 x402；MCP 版只能发现并支付 x402 服务，不能转账或交易 [10][11]。MCP 的单次 / 单会话上限只能在钱包 UI 改，agent 改不了 [12]。
  • Wallet MCP（原 Base MCP）：连接用户自己的 Coinbase Wallet，每笔写操作都要用户批准 [14]。
  • Spend Permissions：链上合约，按代币、额度、周期授权一个 spender；与 CDP Policies（Coinbase TEE 内的链下策略）不是一回事 [13]。

Binance Agentic Wallet：

  • 是 Binance 账户下的独立 keyless 钱包，与主 MPC 钱包分开；开启 Secure Auto Sign 后不逐笔确认 [16]。
  • 安全规则只能在 Binance App 里改，agent 只能读；连接时要在 App 核对 6 位配对码和请求来源 [17]。
  • 转账只能发往地址簿白名单，这一限制不能关闭。Swap 与转账、DeFi、x402、Developer Mode 各有一个 24 小时额度，没有总上限 [18]。
  • Developer Mode 才开放任意合约调用：只能在 App 开启，会过期，默认额度 1,000 USDT，钱包余额超过 10,000 USDT 时不能开启 [17][18]。

OKX Agentic Wallet：

  • 是 Onchain OS 的执行组件。邮箱 / Google / Apple 登录，密钥在 TEE 内生成和签名，一个钱包最多 50 个子钱包 [20]。
  • 默认能力宽：contract-call 接受任意 calldata，sign-message 默认 personalSign [21]。
  • 策略只有四条：单笔限额、日转账限额、日交易限额、转账白名单，由用户在 Web 门户设置 [21]。

BNB Agent Studio：不是钱包，是把部署、钱包、模型付费（x402）、身份（ERC-8004）、任务（ERC-8183）整合在一起的平台 [23]。

  • 钱包后端可替换：默认本地 keystore，另有 TWAK（本地加密）、Altana（链上 session）、Turnkey（enclave 策略）[23][24]。
  • 签名是固定代码，不是 LLM 能调用的工具；IDE 里的 MCP 只有只读工具 [24]。

产品 账户模式 密钥 / 策略层 Mantle

基础设施对照：

基础设施 执行层 绕过点 Mantle
Privy TEE，默认拒绝 key quorum 可改策略 ✓任意 EVM

卡网络路线做对照：Crossmint 的 agent 卡走 Visa Intelligent Commerce 或 Mastercard Agent Pay 时，限额由卡网络执行，agent 看不到卡号；每笔购买走用户自己的卡，退款和 chargeback 照常 [30]。crypto 路线由合约执行限额，但没有对应的退款机制；钱包文档也没写争议由谁承担。

发现

F1

主流做法是“独立预算钱包 + 厂商链下策略”

置信度: high
论断

核心四家都给 agent 一个独立钱包，额度和白名单由厂商服务端、API 或 TEE 执行，或没有公开执行层。由链上合约强制执行的限权，只出现在智能账户路线。

证据

observed MetaMask 策略以 YAML 存在 server wallet [2]；Binance 规则在 API 层 [17]；OKX 策略在 Web 门户设置 [21]。observed Altana 越界即回滚 [26]；Crossmint 权限由合约执行 [30]；Coinbase Spend Permissions 在链上 [13]。speculative Coinbase Agentic Wallet 的限额在服务端或 TEE 执行，文档未写。

影响

评估一个 agent 钱包，先问“策略在哪执行、厂商下线后还有没有效”。

F2

“每笔先确认”多数是 skill 规则，不是服务端保证

置信度: high
论断

逐笔确认多数写在 skill 或工具参数这一层，由 agent 自己遵守。MetaMask 和 Binance 另有有文档的服务端或 App 侧检查。OKX 和 Phantom 的服务端确认条件各不相同，也没有完整公开。

证据

observed MetaMask 规则要求事前确认；服务端在越界、高风险、提额和改策略时强制 2FA [2][4]。observed Binance skill 写明“用户明确要求时可跳过确认”；风险分 ≥4 的交易推到 App 确认或自动拒绝 [18][19]。inferred OKX 的 confirming 可以带 --force 重跑越过 [21]。inferred Phantom 的 confirmed: true 只是参数，perps 写操作调用即提交 [29]。

影响

被注入的 agent 可以越过 skill 层。安全论证只算有文档的服务端、enclave 或链上约束（见 J 的第 3–5 层）。

F3

要防的不是“看到私钥”，而是没有边界的签名能力

置信度: high
论断

你的判断 1 方向对，表述要改。BYOK 和 TWAK 把密钥放在 agent 主机上，能读环境变量的进程就能签名。反过来，策略为空的托管钱包，经济上接近把私钥交给 agent。

证据

inferred MetaMask BYOK 助记词在 MM_MNEMONIC，没有服务端额度 [1][2]。inferred TWAK 签名密码可来自环境变量 [28]。observed Altana：“permissions.calls omitted = unrestricted” [26]。observed Turnkey：“Root users bypass the policy engine entirely” [27]。observed Crossmint 不带 scope 的 signer 可以不受限地花代币 [30]。

影响

给 agent 的权限要同时限定目标合约、方法、金额和有效期，并确认 agent 不是 root。

F4

额度不等于损失上限

置信度: high
论断

你的判断 2 要补上一句：额度只统计已发交易，不含签出去的授权和已有 allowance。暂停 agent 也不会作废它们。

证据

observed MetaMask：Permit2 等签名不计入额度；不经它后端提交的交易计量不准；10 USDC→ETH→DAI 计为两笔各 $10 [3]。observed EIP-3009 授权在有效窗口内任何人可提交，只能 cancel 或等过期 [48]。inferred OKX 策略没有合约和授权维度 [21]。speculative OKX 限额不覆盖授权后第三方转账（GPT 资料的说法，原页面需要登录，未核实）。

影响

停机流程要包含“取消已签授权、撤销 allowance”，不能只在界面上显示“已暂停”。

F5

“确定性执行、减少推理”已是设计共识

置信度: medium
论断

你的判断 3 成立，各家已经这样做：签名和校验由固定代码完成，LLM 只负责选择和规划。

证据

observed BNB Agent Studio：签名是固定代码，不是 LLM 可调用的工具 [24]。observed AP2：各角色的校验“MUST happen in deterministic code” [37]。observed x402 默认流程由代码验签和结算 [34]。

影响

给 agent 的工具要有明确语义（报价、构建、校验、提交、查状态），不要只给一个“发任意交易”。

F6

链上身份不等于一等公民

置信度: medium
论断

你的判断 4 要具体化。ERC-8004 提供身份、声誉、验证三个注册表，不管付款，也承认声誉可以被刷。一等公民还需要预算、收款、可撤销和可审计；BNB Agent Studio 从 v2 起让 agent 收款。

证据

observed EIP-8004：“Payments are orthogonal”；Sybil 攻击可以抬高假 agent 的声誉 [35]。inferred 只有 3%–15% 的注册带有效服务端点 [43]。observed 8004scan 显示 819,538 个 agent，最新条目反馈为 0 [43]。observed Agent Studio v2 让 agent 可以被雇佣和收款 [23]。

影响

衡量 agent 生态看付费任务和收入，不看注册数。

F7

真实付费需求还很小，交易数里有大量刷量

置信度: high
论断

你的判断 5（给 agent 活动空间）方向对，但目前的数据撑不起“需求已爆发”。x402 全网每天约 $44K，30 天交易数下降 46%。BNB Chain 自己写明应用层需求还待证明。

证据

observed Artemis（10-19 更新）：24 小时 101.7K 笔、$44.2K、均值 $0.40；30 天 −45.88% [42]。observed Artemis 单独列出“Real vs. Gamed Transactions” [42]。inferred 二手转述的 Artemis 2025-12 报告：约 48% 笔数、81% 金额与刷量有关 [42]。observed BNB Chain：“application-level demand … still has to be proven” [25]。observed 三家都没有公开钱包级使用数据 [16][20]。

影响

产品指标看独立付费方和重复使用，不看钱包数和交易数。

F8

两种设计思路：默认收窄，或默认放宽再加策略

置信度: medium
论断

Binance 默认只开放验证过的操作，Coinbase MCP 只能付 x402；OKX 默认允许任意 calldata，MetaMask Beast Mode 去掉白名单。收窄的代价是通用性：Binance 做不了 SIWE 登录和空投领取。

证据

observed Binance 不发起任意交易，消息签名只允许 EIP-712 [17]。observed Coinbase MCP 不能 send / trade [10]。observed OKX contract-call 接受任意 calldata [21]。observed Beast Mode 只有威胁扫描 [2]。

影响

按场景发权限：只买数据的 agent 不需要转账和交易能力。

F9

你没列到的四个问题

置信度: high
论断

1）提示注入利用的是 agent 已有的权限，不只是偷密钥。2）撤销不作废已签授权（见 F4）。3）自动化要有常驻进程才会执行。4）付款可能重复：脚本无状态，超时重试会再扣一笔。

证据

observed Anthropic：加防护后攻击成功率 1.4%，“No browser agent is immune” [40]。observed OpenAI 建议 MCP 工具始终开启审批，不让不可信数据直接驱动 agent [41]。observed TWAK 自动化只在 watcher 运行时执行 [28]。observed MetaMask x402 脚本无状态，规则要求每个资源只付一次 [4][6]。observed x402 用 settlement_pending 对账防止二次扣款 [34]。

影响

把“外部内容不能改策略、改收款地址”写进第 3–5 层，并给每笔付款一个幂等键。

F10

Mantle 链层件大多就绪，缺的是 x402 结算路径和钱包覆盖

7702 已启用，4337 有 bundler / paymaster，ERC-8004 的身份和声誉注册表已部署，USDC 和 USDT0 都实现了 EIP-3009。官方 x402 文档没有 Mantle 的默认资产和 facilitator。钱包里 Coinbase、Binance、Phantom 不支持 Mantle；MetaMask 支持但没有威胁扫描。

证据

observed Skadi 升级带来 EIP-7702 [44]；Pimlico 在 Mantle 支持 EntryPoint V06–V09 [45]；8004 注册表地址 [46]。observed x402 默认资产表和 facilitator 列表没有 Mantle [34]。observed Mantle USDC 的 3009 只接受 v,r,s 签名 [47]。observed MetaMask 的 Mantle 行 Transaction Shield = No [5]。
