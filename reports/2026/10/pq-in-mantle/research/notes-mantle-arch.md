# Mantle 架构、预编译设计与双硬分叉兼容策略

## 一、为什么首选“无状态签名验签预编译”，而非通用 NTT 数学原语？

在 Ethereum 核心讨论中（如 pq.ethereum.org），有两种预编译路线：
1. **通用多项式与 NTT 向量数学预编译（Vector Math / NTT Precompile）**：
   - 试图提供底层多项式加减法、NTT 变换等基础算子。
   - 理论上可以支持多种格密码算法（ML-DSA、Falcon、HawK 等）。
   - **Mantle 为何不宜先做这个？**：把签名验证拆解到底层算子，意味着应用层智能合约必须自己组装消息哈希绑定、拒绝采样检查、多项式范数边界校验、提示向量（hint）解码。一旦合约代码稍有瑕疵，就会导致致命的验签绕过！此外，调用多次预编译会带来极大的调用开销与复杂的 gas 计算。
2. **端到端标准化签名验签预编译（Dedicated DSA Precompile）**：
   - 接口接收：`public_key || signature || message`。
   - 接口返回：固定 32 字节（`0x01` 成功，`0x00` 失败）。
   - **优势**：密码学安全边界清晰，经过形式化验证和已知答案测试（KAT），在 Go（op-geth）与 Rust（Kona）两端有成熟独立的密码学库交叉验证，应用层合约只需检查返回值。

## 二、预编译接口设计与规范（借鉴 EIP-8355 / EIP-8051）

### 1. 输入数据编码
输入必须是确定性的紧凑字节流：
```
[0 .. PK_LEN-1]            : 算法标准压缩公钥 (ML-DSA-65: 1952 字节)
[PK_LEN .. PK_LEN+SIG_LEN-1]: 算法标准签名 (ML-DSA-65: 3309 字节)
[PK_LEN+SIG_LEN .. end]    : 被签名的变长消息数据 (通常为 32 字节的 operation digest)
```

### 2. 输出与错误处理（Fail-Closed 原则）
- **静态调用检查**：合约必须使用 `staticcall`，且必须严格校验调用成功（`success == true`）且返回字节长度为 32 字节，且返回值严格为 `bytes32(1)`。
- **防止空地址假阳性**：在以太坊中，如果调用的地址没有代码也没有激活预编译，`staticcall` 也会成功返回空数据（`returndatasize == 0`）。合约层若写成 `if (success) { ... }` 将产生灾难性漏洞！因此合约必须强制要求 `returndatasize == 32 && return_value == 1`。
- **无状态性（Stateless）**：预编译严禁访问链上状态，不存储公钥，不维护 nonce，不处理资产，不判断权限。它只是一个纯数学函数。

## 三、全栈一致性：从 `op-geth` 到 OP Succinct (Kona / SP1)

Mantle 的状态结算已经演进为 **OP Succinct** 架构。这给新增预编译带来了独特的工程约束：

```
+-------------------------------------------------------+
|                   Mantle L2 节点                      |
|                                                       |
|  +---------------------+     +---------------------+  |
|  |   op-geth (Go)      |     |  Kona STF (Rust)    |  |
|  |   (Cloudflare CIRCL)|     |  (RustCrypto ml-dsa)|  |
|  +----------+----------+     +----------+----------+  |
|             |                           |             |
|       执行出块与验证              SP1 zkVM 证明执行    |
|             |                           |             |
+-------------+---------------------------+-------------+
              |                           |
              v                           v
        L2 状态根生成              Succinct SP1 证明生成
                                          |
                                          v
                                   Groth16 / PLONK 包装
                                          |
                                          v
                              Ethereum L1 结算验证合约
```

### 关键工程断言：
1. **双端执行一致性（Dual-Client Equivalence）**：
   - 普通出块节点由 Go 写的 `op-geth` 执行，使用 Cloudflare CIRCL 验签；
   - 证明器运行的是 Rust 写的 `Kona`（在 SP1 RISC-V zkVM 内部执行），使用 RustCrypto `ml-dsa`。
   - 两者必须对**任何**输入（包括非法公钥、超长签名、重复 hint、无效上下文）产生绝对一致的返回与 gas 消耗！必须引入严格的差分模糊测试（Differential Fuzzing）。
2. **SP1 zkVM 内部执行与 SP1 预编译区别**：
   - **EVM 预编译**：EVM 字节码中调用的 `STATICCALL 0x...`。
   - **SP1 预编译（Core Circuit Precompile）**：Succinct SP1 虚拟机为了加速特定耗时运算（如 Keccak-f1600、SHA-256、secp256k1）而在 zkVM 底层构建的专用证明电路约束。
   - 在第一阶段，Kona 内部可以直接调用纯 Rust 实现的 `ml-dsa`。虽然在 RISC-V 虚拟机会消耗较多周期，但在高价值机构账户低频调用的场景下，不会成为整块 Rollup 证明的瓶颈。无需在第一天就定制 SP1 底层 ASIC/电路级预编译。

## 四、EVM 兼容性与 Mantle“双硬分叉”节奏适配

### 1. Mantle 的分叉节奏与工程现实
- Ethereum L1 通常每年进行一次重大硬分叉（如 Dencun、Pectra、Fusaka）。
- Mantle 针对每次 L1 硬分叉，工程实践中执行**两次硬分叉**：
  - **分叉 A（兼容性分叉）**：与 L1 升级同步激活。重点是调整区块派生规则、引擎 API、L1 Gas 计算与系统配置，确保 Rollup 节点不与 L1 脱节，防止链 halt。
  - **分叉 B（特性引入分叉）**：滞后一段时间激活。经过全面测试后，将该 L1 分叉的新 EVM 操作码、系统预编译或新规范正式对 Mantle 用户开放。

### 2. 自定义 PQ 预编译如何避免与 upstream rebase 冲突？

| 潜在风险 | 破坏场景 | Mantle 规避与防护工程策略 |
|---|---|---|
| **地址空间冲突** | Mantle 占用了草案地址（如 `0x12`），后续以太坊将 `0x12` 分配给别的新功能 | **地址隔离策略**：不盲目抢占以太坊 1-20 号系统草案地址；分配至 Mantle 专有扩展地址区间（如 `0x0100` 以上保留区，类似于 OP Stack 的 P256VERIFY 位于 `0x0100`）；待以太坊官方标准出台后再做多地址映射。 |
| **接口与参数漂移** | 以太坊未来标准采用了不同的输入顺序、哈希包装或返回值格式 | **版本化适配模块**：智能账户不直接硬编码预编译地址，而是通过轻量版本化适配器合约（`PQVerifierAdapterV1`）调用。升级时仅需部署 V2 适配器，用户账户做平滑模块切换。 |
| **Rebase 代码覆盖** | `op-geth` 跟随 upstream geth 升级时，分叉预编译注册表被上游代码覆盖 | **插件化注册层**：将 Mantle 自定义预编译注册逻辑收敛在独立的 `mantle_precompiles.go` 文件中，通过 Hook 接入 `PrecompiledContractsCancun` 等上游映射表，并在 CI 中设置自动化回归测试。 |
| **分叉回放一致性** | 历史区块回放时，若预编译在激活区块之前的行为未作封锁，会导致同步分叉 | 严格设置硬分叉激活高度或时间戳（`IsPQForkActive(timestamp)`）；在未激活之前，该地址必须表现为普通未初始化地址（调用返回空数据且消耗基础 gas）。 |
