B-0

Parlia PoSA 与 BLS 快速最终性

~4min
是什么

Parlia 是 BSC 的共识：按质押选出一组验证者，轮流出块，每人连出 16 块。快速最终性是叠加的一层投票。验证者用 BLS 签名对区块头投票，凑够 2/3 就聚合进下一个区块头。

为什么这里需要

New L1 沿用这套共识，只改了三处：出块间隔、验证者上限，以及“投票签什么” [2]（C30、C33）。

最小例子

区块 N 的投票写进 N+1 → N 被 justify；N+1 的投票写进 N+2 → N 被 finalize。200 ms 出块下约 0.5 s [2]（C34、C35）。

常见误解

误解：PoSA 就是 PoA。事实：验证者按质押每天选举，作恶会被 slash；但集合有上限，不是无许可 PoS（C45）。

B-1

异步执行（execution 与 consensus 解耦）

~4min
是什么

传统链在提出区块前就要执行全部交易，区块头里带执行后的 state_root。异步执行把两步拆开：共识只定交易顺序；执行在后台跑，结果写进之后某个区块。顺序一旦确定，结果就确定了，执行只是把它“算出来”。

为什么这里需要

200 ms 里放不下“执行 + 全网重执行 + 投票”。New L1 的整个设计都建立在这个拆分上 [5]（X4、X6）。

最小例子

Monad 把区块 N 的结果写进 N+3；EIP-7886 写进 N+1；New L1 写进 N+D，D 随负载变 [5][31][32]（X20）。

常见误解

误解：异步执行就是并行执行。事实：前者改的是“何时执行”，后者改的是“一个区块内怎么执行”。

B-2

原生 AA 交易

~3min
是什么

用一种新的交易类型（EIP-2718 envelope）把批量调用、代付、passkey 签名、受限 session key 写进协议。节点直接验证，不需要 bundler、EntryPoint 或合约钱包。

为什么这里需要

New L1 的 0x76 就是这种交易，它和 Tempo 的交易高度一致 [7][33]（A1、A34）。

最小例子

一笔 0x76 带 1–64 个调用，只有一个外层签名、一个 nonce、一张回执 [7]（A5）。

常见误解

误解：原生 AA 就是 EIP-7702。事实：7702 是给 EOA 挂一段合约代码；New L1 直接拒绝 7702 交易 [8]（A30）。

B-3

隐私池的 note 模型

~4min
是什么

存进池子的钱变成 note（类似 UTXO）。note 的哈希（commitment）写进一棵只追加的 Merkle 树。花一个 note 时，公开一个 nullifier 防止双花，再用 ZK 证明“我拥有树里的某个 note、金额守恒”，但不说是哪一个。

为什么这里需要

New L1 的 ShieldedPool 就是这个模型，加了一种“从池里调用公开合约”的流程 [9]（P3、P9）。

最小例子

Zcash Orchard 是纯支付；Railgun 能 unshield → 调合约 → reshield [43][44]（P25、P26）。

常见误解

误解：隐私池隐藏一切。事实：存入、取出和调用合约时，金额与目标都公开 [9]（P20）。

[9] Shielded Pool

B-4

同态哈希 LtHash

~l2
是什么

把每条状态（账户、存储槽）哈希成一个长向量，全部向量逐元素相加，得到整个状态的摘要。改一条状态，只要减旧向量、加新向量。安全性依赖格问题 SIS：很难找到一组小系数让向量之和为零。

为什么这里需要

New L1 用它代替 MPT，名字里的“lattice”就来自这里 [10]（P29、P31）。

最小例子

改一条状态：减去旧向量，加上新向量 [10]（P30）。

常见误解

误解：用了格就是后量子签名。事实：LtHash 是状态承诺，不是签名（P37）。

B-5

应用特定排序（ASS）

~l2
是什么

让应用自己决定（或约束）它的交易怎么排序、MEV 归谁，而不是全交给出块者按小费排。

为什么这里需要

用来判断 New L1 的“排序–执行分离”是不是 ASS（N 面板）。

最小例子

Multi-Lane 给应用的合约地址保留容量，但不让应用决定交易顺序（X50）。

常见误解

误解：有了保底容量就有排序权。事实：容量隔离和应用特定排序是两种机制（X42、X50）。

一笔交易怎么走：从 20 ms 到执行最终

机器人发出的 0x76 交易要经过五个里程碑 [3][4]（C27）。图 2 是完整的时序。

阶段 约多久 保证什么 不保证什么
preconfirmed 约 20 ms（目标） 当前出块者签名：交易在第几个位置 执行成功；不会被撤销
ordered 约 1 块 交易在已导入的区块里 不被重组
order-finalized 常见 +2 块，约 0.5 s 顺序不可逆 执行成功
executed 排序后不久；已执行 tip 落后约 D 块 本节点已算出回执 全网认可这个结果
execution-finalized N+D 块最终化之后 结果被承诺且被投票 —

按 D = 1 到论坛给出的最多 8 块推算，执行最终约在出块后 0.6–2 s。这是推算，不是测量值（M1）。文档要求：放款、跨链这类依赖执行结果的事，要等 eth_blockNumber("finalized") 越过交易所在区块 [4]（C28）。

F5

约 20 ms 的子区块是出块者签名的可撤销承诺，不是共识对象

置信度: high
论断

当前出块者在自己的轮次里不断把就绪交易打包成签名切片（SubBlock）广播。它只承诺“纳入、在第几个位置”，不碰投票、fork choice 和最终性。出块者撤回会报 aborted，换人出块会报 superseded。窗口内只追加，后来的高费交易不能插队。论坛提案作者说它 “not implemented at the protocol level … a reputational commitment”。20 ms 本身是目标：文档写约 20 ms，路线图写 sub-50ms，论坛写 20–50 ms。

证据

observed Pre-confirmation 页 Guarantees、Limitations [3]；交易生命周期 [4]；论坛作者回复 [16]（C15、C20、C21、C23、C11）。inferred 20 ms 与 0.5 s 是设计目标，不是公开网络的测量值（C13）。

影响

应用可以用它刷新 UI、给支付回执，但必须处理撤销；不能凭它放款。

没有全局 mempool：Gateway 单跳交给出块者；“防抢跑”只是不广播

置信度: medium
论断

Gateway 是普通全节点，收下交易后保留托管，把副本直接发给按验证者排程选出的下几个出块者；出块者不再转发。没有 txpool_*，当前客户端也没有拍卖或排序 API。路线图说 TxStream “blocking front-running by design”，但文档里的机制只是“不广播到公共 mempool”；出块者本人仍最先看到交易。TEE Gateway（TEE 内加密入口与确定性排序）只是 2026-10-10 的论坛提案。

证据

F7

共识仍是 Parlia PoSA + BLS 最终性，不是 PoA，也不是无许可 PoS

置信度: high
论断

验证者按 BNB 质押每天选举一次，最多 64 个，每 16 块轮换出块者；本轮出块者缺席时，其他人按确定性种子的随机退避补位。BLS 投票凑够 ⌈2N/3⌉ 后由下一个出块者聚合进区块头，按 Casper-FFG 规则判定 justified / finalized，常见情况 +2 块最终化，约 0.5 s。真正的改动是投票只签顺序：验证者本地执行后如果发现 ExecutionCommitment 不对，就不投票，错误结果凑不齐 2/3。文档还说 Parlia 只是 “current default”，正在评估 Minimmit 作为 Consensus 2.0。

证据

observed Consensus 页 [2]；BEP-126 [18]（C30–C34、C36–C39）。inferred 属于有上限、按质押选出、可惩罚的 PoSA（C45）；出块快 2.25 倍（C42）。

影响

F2

真正的新东西是时间结构：区块头不带执行结果，结果晚 D 块写回

置信度: high
论断

F4

按声明的 gas_limit 收费、不退款，是异步执行的代价

置信度: high
论断

共识按“滞后 D 块的状态”接纳交易。所以会放进执行时注定失败的交易：余额已空、同块被掏空、nonce 冲突、授权已变。为了让这些交易照样付区块空间的钱，New L1 规定：按 gas_bid × gas_limit 收费，不退未用 gas，EIP-3529 退款作废；按“在途花费”算出 effectiveBalance，够付才接纳；每个账户在 D 窗口内的在途 gas 和 calldata 有硬上限。回执里的 gasUsed 通常等于声明的 limit。

证据

影响

排序–执行分离 ≠ 应用特定排序；Multi-Lane 只保容量

架构图上写的是 “Order-Execution separation”；正文的意思是“投票签顺序，不签执行结果” [1][2]（X39）。它没有改变“谁决定顺序”。

维度 New L1 排序–执行分离 应用特定排序（ASS）
解决什么 200 ms 下执行不能挡在共识前面 应用自己的交易怎么排、MEV 归谁
谁定顺序 当前出块者，按小费 应用、应用 sequencer 或合约规则

给应用排序权 ✗不给 ✓这是核心
公平排序 / MEV 规则 ✗协议里没有 ✓通常是设计目标

Multi-Lane 是什么。 治理在 LaneRegistry 里给某些合约地址登记一个 bps 配额，例如 1,500 bps 就是区块 gas 的 15% [6]（X44、X45）：

  • 交易按 to 地址确定性地进入 lane；未登记地址和合约创建走默认 lane。
  • 不看 calldata 或 selector：发往登记地址的任何交易都占这个 lane 的配额。
  • 只保容量，不保纳入；lane 内按小费排，不保证 FIFO。
  • 闲置配额回流给默认 lane；占用按声明的 gas limit 计。
F9

排序–执行分离只是时间解耦，和应用特定排序正交；Multi-Lane 是容量隔离

置信度: high
论断

排序权仍在当前出块者手里：Gateway 不提供排序 API，lane 内按小费排，预确认窗口内只追加。所以排序–执行分离不给应用任何排序权，也不改变 MEV 归属。Multi-Lane 给登记的合约地址保底 gas，但不给排序规则，和 Tempo、BSC 的 payment lane 同类。和 BSC Payment Lane（BEP-703，一个支付类、闲置配额不回流）相比，Multi-Lane 有多条 lane，闲置配额会回流。

影响

Native AA：0x76 是 Tempo 设计的 BNB 变体

机器人那笔交易就是 0x76：1–64 个调用整体原子执行，一个签名、一个 nonce、一张回执 [7]（A5）。账户有三级 key，都由 AccountKeychain 预编译（0x…4000）管理 [7]（A11–A13）：

等级 能做什么 限制
root 地址就是账户；部署合约、管理 key 不能撤销，所以 root 不能在同一地址内轮换
admin 授权、撤销其他 key 不能部署；必须无 scope、无上限、无过期
access 普通 session key 受 scope（目标 + selector）、原生币花费上限、过期约束

Alice 的机器人 key 是 access 级：scope 是 DEX 路由合约的 swap。花费上限只算原生币流出，所以它限得住 BNB，限不住 BEP-20 代币（A16、A33）。它也不能用 token_fee：这个功能只允许 root 签名的代付交易 [7]（A22）。

P

隐私池：比支付多一步，离隐私 DeFi 还远

ShieldedPool 是创世预部署的系统合约（0x…5000）[9]（P1）。四种流程 [9]（P9）：

  • Shield：EOA 调 privDeposit 存入，地址、金额、资产都公开。
  • Shielded transfer：池内转账，花 1–2 个 note，总是公开 2 个 nullifier（不够就用假的补齐），产出最多 3 个 note。
  • Unshield：取到普通地址，金额、资产、目的地公开。
  • Atomic call：从池里取钱，调用一个公开合约，把返回值存回池里。

每次花费带两份 PLONK 证明（BN254，各 864 字节）：pool proof 证明金额守恒和 note 归属；auth proof 证明 note 里登记的 EOA 签了 EIP-712 消息 [9][8]（P5、P6）。提交有两条路：0x77 交易没有发送方、nonce 和外层签名，证明本身就是授权；或者交给 relayer 调用 transact [9]（P11、P12）。

流程 公开什么 隐藏什么
Shield 存款地址、金额、资产 之后谁持有
池内转账 direct 路径的手续费 发送方、收款方、金额、资产
Unshield 金额、资产、目的地址 note 历史
Atomic call unshield 金额、调用目标、calldata、reshield 金额 谁在调用
F12

隐私池能用池内余额调用公开合约，所以不只是支付；但它不是隐私 DeFi

置信度: high
论断

Atomic call 让池内余额触发一次公开的 EVM 调用，结果以 open note（owner 隐藏、金额和资产公开）回到池里。DEX 合约、调用目标、calldata、金额都公开；只有 Alice 和这次调用之间的关联被隐藏。调用回滚时，花费照样成立，托管的钱可以重试；Railgun 的同类流程是整体回滚。资产只支持原生 BNB。

证据

observed Privacy 页 Flows、Current Status、Security Assumptions [9]；交易类型页 [8]；Railgun 文档 [43]（P8、P18、P19、P25）。inferred 可组合性是“用池内余额触发一次公开调用”，不是隐私执行（P24）。speculative atomic call 能否调用任意合约，文档没写（P27）。

影响

回答“是否只是 private payment”：不是，它能接 DeFi；但 DeFi 本身全公开，所以只是“匿名地使用公开 DeFi”。

F13

隐私池现在不能放真钱：未审计、导入别人的 SRS、只支持 BNB

置信度: high
论断

文档的警告原文是 “Do not treat it as safe for real value”。PLONK 用的 SRS 是导入的现成公共参数；自办仪式和第三方电路审计仍是主网前的未决项。未实现：ERC-20 / BEP-20 隐私、预留的 PQ 授权、paymaster / 4337 提交、合规钩子（只有接口缝）、递归证明聚合。合约不可变，治理只能暂停存款。

证据

observed Privacy 页 [9]；FAQ [13]（P7、P17、P21–P23）。inferred 路线图宣传的 “selective disclosure for compliance” 在文档里还没有落地（P46）。

影响

隐私能力目前是“设计 + devnet 演示”，不是可用产品。另外两处元数据泄露：注册隐私地址会公开关联 EOA；relayer 能看到 IP 和时间。

Q

PQ：“格”只用在状态承诺上

New L1 不用 MPT。每条状态（账户、非零存储槽）是一个 KV 条目，图 5 是它变成 state_root 的过程 [10]（P28、P29）。

它是怎么用 PQ 的？ 只在一处：文档说累加器的安全性基于 SIS 格问题，1024 × u16 “targets ~128-bit security”，参考 Bellare–Micciancio 1997 和 Solana SIMD-0215 [10]（P31）。下表是全栈每个组件的密码学 [2][7][9][10][45]（P40–P43）：

组件 用的是什么 是否 PQ
共识投票 BLS 聚合签名 ✗
账户签名 secp256k1、P256、WebAuthn ✗
子区块签名 65 字节可恢复签名 ✗
隐私证明 PLONK on BN254 ✗
隐私授权 EOA 签 EIP-712（PQ 方案预留、未实现） ✗
状态承诺 BLAKE3 + LtHash（基于格问题，不是签名） !部分
F14

LtHash 是状态承诺，不是 Falcon；New L1 全栈没有 PQ 签名

置信度: high
论断

Falcon（FN-DSA）是格基签名：私钥签、公钥验。LtHash 是同态集合哈希：把整个状态压成一个可增量更新的摘要。两者都和格有关，用途不同，New L1 文档里也没有 Falcon。BLS、secp256k1 / P256 / WebAuthn、BN254 PLONK 都是椭圆曲线密码，NIST 认定这类方案会被 Shor 算法攻破。路线图的 “Post-Quantum Readiness” 是全 BNB Chain 的研究计划（混合方案、用 AA 免换地址升级），New L1 一节只把 LtHash 当作提速手段。

证据

observed State DB [10]；路线图 [14]；NIST IR 8547 [45]（P29、P31、P44、P45、P42）。inferred LtHash 不是签名（P37）；各组件都不是 PQ（P43）。

影响

不能把 New L1 称为“后量子 L1”。“lattice-based state commitment” 是准确说法。

F15

同一组 LtHash 参数在 2026-09 被公开了约 2^81 次查询的碰撞攻击，文档还写 ~128-bit

置信度: medium
论断

ePrint 2026/2083（2026-09-18）对 LtHash16（N = 1024，d = 16，Facebook 和 Solana 在用）给出约 2^81 次哈希查询、不超过 2^101 次运算的碰撞攻击。SIMD-0215 在 2026-09-25 改写了安全一节，承认这个攻击。它论证碰撞集合约有 2^72.83 个元素，而 lamports 非零的账户少于 2^65，所以构不成合法状态。New L1 用同一组参数，但条目编码不同（包括存储槽）；它 2026-10-22 的文档仍只写 “~128-bit”。

证据

observed ePrint 2026/2083 摘要 [41]；SIMD-0215 @f1afd94 安全一节 [40]；State DB [10]（P32–P34）。inferred 文档没反映这次更新（P35）；Solana 的反驳只适用于 Solana 编码，New L1 需要另做论证（M7）。speculative Solana 的论证不能直接套用到 New L1（P36）。

影响

这不是可直接利用的漏洞。但 New L1 要针对自己的状态编码重新论证碰撞安全。

F16

没有 MPT 的代价：eth_getProof、snap sync 不可用，桥要另想办法

置信度: medium
论断

累加器是“和”而不是树，没有包含路径，所以 eth_getProof 永远返回 -32004，snap sync 不存在，整状态 debug 读取也不支持。在“accumulator-native”包含证明发布前（文档说 planned），桥和轻客户端只能靠 BLS 最终性投票和全节点响应。BSC↔New L1 原生桥还在开发，CrossChain 地址目前是占位。累加器每块归档 2 KB，约 0.9 GB/天。

证据

observed State DB [10]；迁移指南 [11]；Network info [13]（P38、P39、C2、M2）。

影响

依赖 MPT 证明的跨链方案、轻客户端和索引工具都不能直接接入。

R

对我们的意义

以下是事实前提加推论，不是对 BNB Chain 的建议。

  1. ASS 设计：New L1 只给了一半。 Multi-Lane 和前文建议的“外层按类别分配容量”是同一层；New L1 没有“内层按类别选排序规则”（M5）。New L1 不能直接作为 ASS 的参照实现，只能参照它的容量配置（LaneRegistry + 治理 + 闲置回流）。
  2. 预确认：强度一样，都是出块方单方承诺。 New L1 的 SubBlock 和前文所述 Mantle 的 FIFO preconf 车道一样，都不由共识保证（M6、F5）。New L1 的可借鉴之处在接口：签名切片、撤销状态（aborted / superseded）、客户端自验步骤 [3]。
  3. 异步执行：代价已经写清楚了。 评估“执行移出关键路径”时，要同时设计接纳规则（M4、F4）。可选做法：按声明 gas 收费加在途花费上限，或 Monad 式 reserve balance。RPC 语义（latest = 已执行）也要跟着改。
  4. Native AA：Tempo 式固定方案已有两条链采用。 前文建议先做 8130 PoC；现在“协议固定 + 0x76 schema”路线多了一个采用者（M3、F10）。与 New L1 固定的签名方案不同，8130 的可插拔 authenticator 不用升级协议就能加 PQ 算法（F11）。
  5. PQ：不要把 LtHash 当作 PQ 方案。 如果考虑 LtHash 做状态承诺，要按自己的条目编码重新论证碰撞安全（M7、F15）。
CAUTION

以上第 2 条依赖前文对 Mantle preconf 车道的描述；本篇没有重新核对 Mantle 代码。
