背景动机

问题：在传统 DEX 上发一个新币，创作者要自己垫资做双边 LP，还能随时撤池。散户怕撤池，bot 抢第一个区块。Launchpad 用合约承担做市，把这三个问题变成了代码问题。

为什么现在：

  • Mantle 上的两次尝试都已停止运营：Funny Money（2025-02 推出，定位 AI agent launchpad 与 DeFAI 终端）和 Printr（多链 launchpad，2026-08 停止运营）[23][24]。
  • Agent 发币和交易已在 Base 和 Robinhood Chain 上跑通（Bankr、Clanker）[25][13]。
  • Mantle 正在规划 agent 第一公民的 launchpad，需要一份让开发者能接手讨论的材料。

范围：机制与数学、完整生命周期、主要产品复盘、结构性缺陷、agentic 方案的设计依据。

非目标：Tape（以 xStocks 计价的 launchpad 方案）；合规细节；排期与 KPI；投资建议。

前置知识

B-0

恒定乘积 AMM（constant product AMM）

~5min
是什么

池子里有两种资产 x 和 y，交易前后保持 x × y = k。买走 y 越多，剩下的 y 越贵。

为什么这里需要

launchpad 的曲线就是这个公式，只是把储备的一部分换成了“虚拟”数字。

最小例子
池子：x = 10 SOL，y = 1000 枚，k = 10000
买入 1 SOL → x = 11，y = 10000/11 ≈ 909.1，得到约 90.9 枚
常见误解

误解：价格由人工挂单决定。事实：价格只由两边储备的比值决定。

B-1

虚拟储备曲线（virtual-reserve bonding curve）

~8min
是什么

在恒定乘积公式的两边各加一个常数，作为不存在的“虚拟”储备。合约用这条曲线给每一笔买卖报价。

为什么这里需要

纯真实储备下，开盘时 SOL 储备为 0，价格就是 0，第一笔买单能几乎免费买空；最后一枚代币的价格又趋于无穷，曲线卖不完。虚拟储备同时解决这两个问题。

最小例子
pump.fun：(x + 30) × (y + 2.799e8) = 3.219e10
开盘价 30 / 1.073e9 ≈ 2.80e-8 SOL
常见误解

误解：虚拟储备是平台垫的钱。事实：它只是公式里的常数，任何人都取不走。

B-2

集中流动性与单边流动性（concentrated / single-sided liquidity）

~6min
是什么

集中流动性让 LP 只在一个价格区间内做市。单边流动性是区间全部位于现价一侧，只放一种资产。

为什么这里需要

Clanker、Zora、PAIR 把全部新币放成单边头寸，价格上涨时才吸收 quote。这一个头寸就起到曲线的作用，所以不需要毕业。

常见误解

误解：单边池开盘时有对手盘。事实：池里只有新币，第一个买家没有任何竞争价格。

B-3

Uniswap v4 hook

~8min
是什么

建池时绑定的一个合约，在 swap、加减流动性前后被调用。它能改写 swap 的数量和手续费。

为什么这里需要

衰减税、持仓上限、费用路由和“池内毕业”都写在 hook 里。所有池子由一个 PoolManager 管理，建池只是一次状态更新。

最小例子
hook 地址的低 14 位是权限位
beforeSwap = 1 << 7
beforeSwapReturnDelta = 1 << 3
常见误解

误解：建池后可以换 hook。事实：hook 是池子标识的一部分，不能更换。

B-4

狙击与 MEV（sniping / MEV）

~5min
是什么

狙击是 bot 在新币开盘的第一个区块抢先买入。MEV 是出块排序带来的额外收益，例如夹子交易。

为什么这里需要

虚拟储备曲线非常“前置”：净入 30 SOL 时，已经卖出 53.65% 的总供应。所以越早买，拿到的份额越大。

常见误解

误解：狙击是治理问题，禁掉 bot 就行。事实：它来自曲线形状，协议只能用延迟、衰减税、持仓上限来缓解。

B-5

账户抽象与 session key（account abstraction / session key）

~8min
是什么

账户抽象让账户本身是合约，能自定义签名校验规则。session key 是主人签发的临时密钥，只能在规定的合约、函数、额度和时间内使用。

为什么这里需要

agent 需要自己发币和交易，但不能拿到主人的根私钥。EIP-7702 让普通 EOA 委托给合约代码；ERC-4337 提供 Paymaster 代付 gas 和二维 nonce。

常见误解

误解：EIP-7702 自带额度和白名单。事实：7702 只写入委托；限额要靠委托合约或 ERC-7579 模块实现。

生命周期：一个代币从创建到外盘

曲线价格示意（pump.fun 经典 SOL 曲线，由公式算出 [1]）：

净入 SOL 已售占总供应 价格（SOL） 相对开盘
0 0% 2.80e-8 1×
10 26.82% 4.97e-8 1.78×
30 53.65% 1.12e-7 4.0×
60 71.53% 2.52e-7 9.0×
85.0（毕业） 79.31% 4.11e-7 14.7×
(x+30)×(y+2.799×108)=3.219×1010

开盘价 P0=301.073×109≈2.80×10−8 SOL。前 30 SOL 就卖出了一半以上的供应，最后 25 SOL 只卖出约 7.8%。这就是开盘狙击有利可图的数学原因（B-4）。

每个阶段的要点：

  1. 创建：创建免费 [2]。创建和首笔买入可以放在同一笔交易，这就是 dev buy [4]。
  2. 曲线交易：每笔 1.25% 手续费，创作者 0.30%、协议 0.95% [2]。合约层没有反狙击，只有滑点参数 max_sol_cost / min_sol_output [1]。
  3. 毕业判定：在 buy 指令末尾检查 real_token_reserves == 0 [1]。常说的“$69k 毕业”只是 410.88 SOL 毕业市值按当时 SOL 价格换算的结果。
  4. 迁移：migrate 无需许可且幂等，任何人都能调用 [1]。早期由链下服务器把资金搬到 Raydium（withdraw 指令，已禁用）[1]。2025-03-20 起迁入自家 PumpSwap，迁移费从 6 SOL 降到 0 [5]。
  5. 外盘：毕业后的 canonical 池按市值分档收费 [2][4]。
  6. 长尾：大多数币停在曲线上，或毕业后归零。在 v4 上，建池只是 PoolManager 的一次状态更新，不部署新的池合约 [9]。
CAUTION：2026 年的 pump.fun 不再完全符合经典曲线

资料作者在 2026-09 抽样到只注入 0.086 SOL 的迁移，而且代币总供应不等于 10 亿。原因可能是 Mayhem 模式（AI agent 在前 24 小时交易），本文没有核实。集成 pump.fun 时读链上账户，不要硬编码常数。

毕业的三种实现

类型 代表 资金路径 残留问题
A 迁到外部 DEX pump.fun 早期（Raydium）、four.meme 跨协议建池 预建池、链下执行者
B 原子迁到自有池 pump.fun 现在、Pons V2 单笔交易内建池并处置 LP 毕业瞬间的信息冲击
C 不设曲线 Clanker、Zora、Flaunch、PAIR 没有搬运 开盘狙击
  • C 类为什么可行：v4 用一个 PoolManager 管所有池子，建池只是状态更新；hook 可以在 beforeSwap 里覆盖手续费，这正是 Clanker 和 Zora 实现衰减税的接口 [8][9]。
  • “hook 内曲线 + 就地翻转”：技术上可行。hook 有 beforeSwapReturnDelta 权限，可以改写 swap 的数量，用自定义曲线报价 [8]。但调研没有找到按这种方式上线的生产产品（推测，检索不完整）。Pons V2 是“独立曲线合约 + 毕业时铸 v4 头寸”，属于 B 类 [18]。
  • “v4 方案零 MEV”不成立：池内相变只消除了“迁移那一下”的窗口。曲线阶段的抢跑和夹子仍然存在。

M

结构性缺陷与设计公理

F1

迁移是 EVM launchpad 最大的工程攻击面

置信度: high
论断

four.meme 在 2025-02-11 和 2025-03-18 两次被盗，根因都是迁移目标池的价格或地址可以被第三方抢先确定。之后的产品要么原子迁入自有池，要么根本不迁移。

证据

observed Verichains 复盘：池已存在时不校验 sqrtPriceX96，损失约 $183K [10]。observed 第二次是可预测的 pair 地址被抢先注资 [11]。observed 2025-03-31 改为迁到 PancakeSwap V2 并销毁 LP [12]。

影响

设计毕业流程时，不要把资金交给一个任何人都能初始化的外部池。用 B 类或 C 类（见 K）。

F2

开盘狙击来自曲线形状，协议只能缓解

置信度: high
论断

经典曲线净入 30 SOL 时已卖出 53.65% 的供应。各产品用延迟、衰减税、持仓上限、固定价窗口来缓解，没有一家消除它。

证据

inferred 由曲线公式算出（见 J 的价格表）[1]。observed Clanker 衰减税推荐 80% → 5%/30 秒 [13]；Zora 99%/10 秒 [16]；Bankr 14 秒衰减加 5 分钟 2% 持仓上限 [25]。

影响

防狙击参数要和出块时间匹配。出块越快、越可预测，衰减窗口内的档位越多。

F3

创作者永续分成取代了一次性奖励，但买不到留存

置信度: medium
论断

pump.fun 从“毕业奖励 0.5 SOL”变成每笔分 0.30%；Zora、Pons、PAIR、Bankr 都按成交量分成。投机流量消失时，分成也随之归零。

证据

observed pump.fun 2024-08 的 0.5 SOL 奖励与 2025-05 起的交易分成 [7][2]。observed Base App 7 个月发放约 $450K 给约 17K 名创作者，人均约 $26 [22]。inferred “分成能减少老鼠仓”没有量化证据。

影响

把分成写进合约，但不要把它当成留存手段。

F4

多种 quote 资产导致流动性碎片化，至今没有生产级解法

置信度: medium
论断

每个 quote 一个池，池间没有再平衡。股票代币作 quote 时，单个 meme 池能吸走一只股票代币的大部分链上流通量，休市时价格严重偏离。

证据

observed PAIR 接入 AMC 后周末链上价格冲到真实价格的 35 倍，peg guard 只暂停新发射且尚未上线 [19]。observed 一个 HIMS 计价池持有约 53% 的链上代币化 HIMS（另一份研究给出 81%，口径不一致）。

影响

多 quote 必须配统一路由和休市熔断；否则先只开一个 quote。

F5

补贴和分发只能买到冷启动

置信度: high
论断

Base App 下线 Creator Rewards，官方后来承认社交发币路线失败。Robinhood Chain 的 gas 补贴 2026-09-29 到期，之后 launchpad 成交明显回落。Printr 停运的官方原因也是资本与分发不足。

证据

observed Base App 2026-02 下线 Creator Rewards；2026-07-15 Pollak 写道 creator coins “disintegrated completely … I was definitively wrong” [22]。observed 补贴为期 90 天，09-29 到期 [21]。speculative 到期后 Pons 日费下降约 78%，只有二手报道 [37]。observed Printr 停运公告 [24]。

影响

KPI 看毕业数和毕业后存活率，不看发币数。

F6

零门槛发币会稀释单币价值

置信度: medium
论断

发币几乎免费时，供给可以被 bot 和 agent 无限刷，单币平均价值持续下降。

证据

observed Pollak 公开承认社交发币路线失败 [22]。speculative Clanker 单币手续费从 2024-12 的 $1,371 降到 2026-08 的 $53（资料从 DefiLlama 拉取，本轮未复核）。inferred Bankr 需要配额、钱包年龄、IP、余额四层闸门，说明零门槛必须配反女巫 [25]。

影响

agent 发币零门槛之前，先设计发射配额。

F7

管理员权限是第三方信任风险

置信度: medium
论断

合约本身没有漏洞时，掌握提款或配置权限的人仍然可以取走资金。

证据

observed 2024-05-16 pump.fun 前员工利用 withdraw authority 取走约 12.3K SOL（约 $1.9M）[6]。observed Pons locker 写明“包括协议在内，没有人能提取” [18]。

影响

关键比例和收款人写进不可变合约；保留的管理权限要能在链上看到。

由上面推出的设计公理（均为推断）：

  1. 不依赖外部建池的迁移：用单边 LP，或同 quote 池内毕业。
  2. 防狙击参数和出块粒度匹配，或改用额度、竞价门禁。
  3. 创作者分成写进合约并随成交量流动，但不当成留存手段。
  4. 多 quote 必须有统一路由；休市期间要有熔断。
  5. 补贴和分发只买冷启动；KPI 看毕业数和存活率。
  6. 关键比例和收款人写进合约，管理权限公开可查。

为什么让 agent 当第一公民

现有 agentic 产品把权限放在哪里：

产品 第一公民 权限放在哪 可借鉴
Bankr 托管钱包上的 agent 服务端策略：日限额、单笔限额、收款人白名单 配额、未上链退配额、机器可读失败码
Clanker Droid 人类创作者 agent 不碰钱（“not autonomous with your money”） 手续费养推理的资金回路

F8

已有 agentic 产品缺的是链上可验证的权限

置信度: high
论断

Bankr 已经让 agent 既发币又交易，也有限额，但限额在 Bankr 服务端执行。ElizaOS 把根私钥放在环境变量里。Clanker Droid 干脆不让 agent 动钱。方案的差异点应表述为“策略在链上、可验证、不依赖托管方”。

证据

observed Bankr 默认日限额 $500、单笔 $500，“任意合约调用”默认开启，策略由服务端执行 [26]。observed Bankr 警告泄露 agent 权限的 key 可能丢失账户全部资产 [26]。observed ElizaOS 必填 EVM_PRIVATE_KEY [29]。observed Droid 文档 [27]。

影响

宣传和设计都不要说“别人没有限额”；要说“限额写在链上，泄露 key 也突破不了”。

F9

“发币零门槛、交易硬限权”把损失限制在 session 边界内，但挡不住白名单内的亏损

置信度: high
论断

方案的理由是：发币输入少、分支少，适合交给 LLM；交易有滑点、MEV、预言机跳价，必须关在白名单里。Session 能防止资金被转走，但被注入的 agent 仍可以在白名单内反复高价买入。

证据

observed product.md 的定位原则“发币零门槛，交易硬限权；把机器智能放进带有物理闸门的链上沙箱” [38]。observed 主流 session 模块不配 policy 时默认是 sudo，过期时间必须显式设置 [33]。inferred 白名单内的亏损需要额外约束，例如最大回撤。

影响

Session 一定要显式设置过期时间和额度；考虑加最大回撤或“只能买本工厂代币”的约束。

F10

“手续费养推理”已被三家验证

置信度: medium
论断

发币 agent 从交易手续费中拿一部分，用来付推理和 gas。Clanker、Bankr、Virtuals 都这样做；方案的 70%–80% 和 Virtuals 同一量级。

证据

observed Clanker Droid 默认切 LP 奖励的 10% [27]；Bankr 创作者拿成交额的 0.665% [25]；Virtuals 1% 交易税的 70% [28]。observed 方案提出约 1% 手续费、70%–80% 进 agent 的 runtime vault [38]。

影响

费用接收方在发射时写死；runtime vault 只收 quote，人类事后不能改到自己的地址。

O

方案设计：权限、资金与链需求

以下按 product.md（方案主线）陈述，“方案提出”表示这是设计，不是已上线的事实 [38]。

Session 的四层约束（方案提出）：

  1. 目标白名单：只能调用 LaunchpadFactory 和 Router；禁止原生 transfer 和任意 ERC-20 调用。
  2. 函数选择器白名单：launch(name, symbol)、buyExactQuote、sellExactToken、claimFee；禁止 approve(任意地址)。Router 内部原子完成 approve + swap。
  3. 额度：单笔、单区块、生命周期累计三档（按 quote 计），加滑点硬约束。
  4. 时效与撤销：例如 24 小时自动失效；Owner 随时在链上撤销。

这些约束在现有标准里有实现路径。Rhinestone Smart Sessions 可用于任何 ERC-7579 账户，提供调用、花费、时间、次数等 policy [33]。多个 policy 同时生效。

  • 人类入口：Bybit AI Subaccount 已在 2026-05-27 上线：资金隔离、碰不到主账户、只能通过 API 访问 [34]。公告没有提到映射到链上 session；这一步是方案设想（推测）。
  • Agent 入口：Moltbook 是只允许 agent 发帖的社交网络，2026-01 上线，2026-03 被 Meta 收购 [35]。方案把它作为可选的发现层，不替代发射 API。

对 Mantle 链的需求：

需求 方案要什么 现状与实现路径
Session 权限 用 EIP-7702 做 session Mantle 主网已有 7702 授权交易 [36]；限额靠委托合约或 7579 模块
用 quote 付 gas 协议级 Paymaster ERC-4337 有 paymaster 字段 [31]；用股票代币付 gas 需要价格源（开放问题）
二维 nonce 发币和转账分通道 4337 已有 192 位 key + 64 位序号 [31]；原生 RIP-7712 仍是草案
突发负载 必然 revert 的交易快速失败 报告认为不改排序器做不到；链规划把它列为第一包
F11

方案的链级需求大多可以先在 L2 应用层起步

置信度: medium
论断

7702 已在 Mantle 主网可用；二维 nonce 和 Paymaster 由 ERC-4337 提供。报告的推荐是维持 L2，只有 F1–F3 三个条件被 Mantle 自己测到时才开 L3。

证据

observed Mantlescan 的 7702 授权列表（搜索快照约 6 万条）[36]。observed 4337 的 nonce 结构与 paymaster 字段 [31]。inferred 报告“L2 做不到二维 nonce”只对 EOA 和 7702 原生交易成立。observed 报告的 F1 热点外溢、F2 失败扣费导致做市退出、F3 开盘被共址 bot 垄断 [38]。

影响

v1 先验证 Mantle 上 EntryPoint、Bundler、Paymaster 的可用性（开放问题 1）。

合约按固定公式给每笔买卖报价的定价曲线；launchpad 多用加了虚拟储备的恒定乘积。
