# 0002：报告页内的语言切换与推特卡片模式

- 状态：已采纳
- 日期：2026-10-16
- 规格：[../product-spec.md](../product-spec.md) §4.1、§5

## 背景

1. 双语报告的“English / 中文”链接原本注入在返回链接那一行的右侧。桌面上 am 的工具栏是 `position: fixed` 的右上角浮层，正好盖住这个链接，读者只能回首页切换语言。
2. 需要一种比“5 分钟总览”更浅的阅读深度：在 X 上引用（quote）一条源推文时直接贴一张图，让刷推的人一眼看完背景、现状和我们的调研结论，并且能一键复制图片，不用下载。

## 决定

### 1. 两个功能都在 `rh build` 注入，不改 am、不重新渲染报告

- 语言切换和卡片模式都依赖站点信息（有没有英文版、有没有卡片图、发布路径），属于站点外壳，和已有的返回链接同一层。
- 在构建时注入可以覆盖全部已发布报告，不需要 `rh render --force` 重新渲染（已发布 HTML 不自动重渲染，规格 §6.3）。
- `decorateReport()` 是唯一的注入入口；`rh check` 的手机检查用同一个函数生成部署版 HTML（`deployedReportHtml()`），检查的就是线上页面。
- 注入的样式只作用于注入的元素（`data-rh-*`），外加卡片模式下隐藏正文的一条规则。这不是 §6.1 禁止的“手机 CSS 补丁”：它不修改报告自身的排版。没有英文版、也没有卡片的非 am 页面不注入任何样式与脚本。

### 2. 语言切换的位置

- 桌面：am 工具栏的第一个元素（右上角，和主题 / 明暗选择并排）。
- 窄屏（≤ 760px）：am 工具栏几乎占满一行，再加按钮会溢出；切换显示在返回链接那一行的右侧（工具栏正下方），工具栏里的那份隐藏。
- 两种语言的面板 id 相同，切换时带上 `location.hash`；选择写入首页也在用的 `localStorage.rh_lang`。

### 3. 推特卡片：authored YAML + 本地 Chrome 渲染成 PNG

- **内容由 agent 写**（`card.yml`），因为 `rh` 不调用 LLM；卡片不能从 explainer 自动摘取，各报告的总览结构不统一，自动摘要也给不出“背景 / 现状 / 发现 / 结论”的取舍。
- **深度控制分两层**：schema 固定版块、条数（发现 2–3 条，有配图时通常 2 条）和每段显示宽度上限（汉字算 2、ASCII 算 1）；`rh card` 在固定画布上排版并测量，超出画布、数字放不下一行、横向溢出都算失败。字号固定，不允许“缩小字号塞进去”。
- **画布 4:5（600×750 CSS px，导出 ×2 为 1200×1500）**：X 手机端单图按原比例显示的上限附近；比 16:9 能放下“背景 + 现状 + 配图 + 2 条发现 + 结论”且字号在手机信息流里仍可读。
- **预渲染 PNG 并提交到仓库**，而不是在浏览器里把 HTML 转成图片：浏览器端 SVG foreignObject / canvas 方案在 Safari 上会污染画布、字体不稳定，还要引入第三方库；预渲染的 PNG 像素确定，CI 上不需要 Chrome。
- **新鲜度**：PNG 的 tEXt 块里写入卡片内容（与水印）的哈希。`rh check` 发现 `card.yml` 改过而 PNG 没有重新渲染时报错（published 报告为错误，draft 为警告）。哈希只覆盖 `card.yml` 的内容，`meta.updated` 变化不会让卡片“过期”。
- **复制**：`navigator.clipboard.write([new ClipboardItem({"image/png": fetchPromise})])`。`ClipboardItem` 在点击处理函数里同步创建（Safari 要求在用户手势内调用）。需要安全上下文（线上 https 或 localhost）；失败时提示右键 / 长按复制。图片 `loading="lazy"` 且默认隐藏，不打开卡片模式就不下载。
- **卡片模式与 am 阅读路径互斥**，但不复用 `data-am-path`：卡片模式不写入 am 的 `localStorage`，重新打开报告仍是上次的阅读路径；地址栏锚点 `#tweet-card` 可以直接打开卡片模式。
- **配图用 Excalidraw，由 answer-me-with-html 烘焙**：`card.yml` 的 `figure.excalidraw` 与 explainer 的 excalidraw 代码块规格相同。`rh card` 生成一个只含配图的 am 稿件（`.rh/cards/<slug>/`），`am render` 一次烘焙所有语言的图，再从页面里取出自带字体的 SVG 放进卡片。这样复用了 am 的布局检查（重叠、边标签放不下）与手绘字体，研究页和卡片的图风格一致。图区约 508×132；渲染时测量图里每段文字缩放后的实际字号，小于 16px（手机信息流里约 9.6px）算失败——只看缩放比例不够，因为 am 的分组标签固定 14px，所以分组标题改用 `texts`；有配图后发现上限改为 2–3 条，顶栏的品牌与日期并入页脚，以腾出高度而不缩小字号。配图是必填项。
- **中立立场**：卡片以中立研究者身份公开发布，尽量不提 Mantle，不写给某家公司的建议。`rh.config.json` 的 `cardAvoidTerms`（默认 `["Mantle"]`）出现在卡片任何文字（含配图）里时，`rh card` 与 `rh check` 给警告而不是错误——确有必要点名时由用户决定。
- **推文文案（`tweet`）**：与卡片一起写在 `card.yml`，用 X 开源的 `twitter-text` 计数（自己复刻的规则在链接与 emoji 上会算错）。上限是账号属性，放在 `rh.config.json` 的 `cardTweetMax`（非会员 280，当前会员账号 1000），schema 只兜底 X 的硬上限；会员长文在信息流里约 280 之后折叠，所以第一段要 ≤ 280 并能独立成立（`rh card` 打印并警告）。文案不画进图片，所以不计入 PNG 的内容哈希，改文案不用重新渲染；页面上显示文案、X 计数和“复制文案”。文本和图片分两次复制、两次粘贴：一个剪贴板条目同时放文本和图片时，X 的发推框只会取其中一种。复制文案的降级路径把临时 textarea 放在卡片区里（卡片模式下其他内容被隐藏），并检查 `execCommand` 的结果，失败时选中文字、提示手动复制。
- **只有英文版**：推特统一用英文发，所以卡片与推文只有一份英文的 `card.yml` / `card.png`，中英文报告页共用（按钮与提示跟随页面语言）。schema 拒绝任何字段（含配图标签）里的中文。早期的 `zh` / `en` 分语言写法与 `card.en.png` 已移除。
- **版式**：背景与现状用“彩色小标签 + 左侧色条”的分段，结论框同样用小标签；页脚左边是日期，右边是水印（`rh.config.json` 的 `cardHandle`，如 `@whisker17`）。水印画进了图片，所以计入 PNG 的内容哈希：换水印后 `rh check` 提示重新渲染。早期页脚里的论断台账统计已去掉。
- **孤立的卡片图是错误**：`card.yml` 删了而 `card.png` 还在时，构建会继续展示一张无法核对的旧图，`rh check` 按完整性问题报错。
- **审查**：卡片与推文交给 astra-6 subagent（`mantle/gpt-6-astra`）审到 PASS（英文报告 `explainer.en.md` 仍按 AGENTS.md 交给 sol）。
- `quote`（源推文地址）只在页面上显示为链接，不画进图片；图片里也不写站点地址（私有报告的地址对外不可用）。

## 后果

- 新报告的流程多一步可选的 `rh card`；给已发布报告补卡片只需 `card.yml` → `rh card` → `rh publish --note "推特卡片"`。
- 卡片会公开出现在 X 上：私有报告做卡片前要和用户确认可公开的内容，并按中立立场改写（写进了 skill）。
- 每张卡片 PNG 约 0.5 MB，进仓库并随报告部署。
- am 工具栏或阅读路径的标记（`class="am-toolbar"`、`class="am-paths"`）改名时，注入会退化为“放在返回链接一行”的通用位置；`test/build.test.ts` 覆盖了两种位置。
