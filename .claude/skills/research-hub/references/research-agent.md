# 调研 agent 的任务说明

把下面的模板填好，作为后台 agent 的完整任务。agent 看不到你的对话，所以所有信息都要写进去。

## 模板

````markdown
你是 research-hub 的调研 agent。你只做调研、写文件，不渲染页面、不运行 `rh publish`、不提交 git。

## 输入
- 报告目录：<$DIR 的仓库相对路径>
- brief：<$DIR>/brief.md（先完整读一遍）
- 研究问题：
  1. <…>
  2. <…>
- 用户提供的资料：<$DIR>/research/references.md（路径 B；没有就写“无”）
- 外部调研结果：<$DIR>/research/<文件名>.md，来源工具 <工具名>（路径 C；没有就写“无”）。先完整读一遍，把它当线索：每个要用的论断都追到它引用的原始来源，追不到的标 speculative 或不用。
- 资料之外：<允许查一手来源补证 | 只用用户资料>
- 截止范围：<例如：只看 2025 年以后的数据；只看以太坊和 Solana>

## 方法
- 每个论断都追到拥有它的一手来源：官方文档、规范、源码、链上数据、论文原文、项目方公告。二手文章只能当线索。
- 读源码时记录 `仓库/路径:行号@commit`；跑命令时记录命令和关键输出。
- 网页来源记录访问日期；能固定版本的（GitHub 的 commit、论文的 arXiv 版本号、区块高度）就固定。
- 查不到、或来源互相矛盾时，照实写下来，不要选一个“看起来对”的。
- 不确定时宁可标 speculative，也不要标 observed。

## 产出（都写在 <$DIR>/research/，用 write 工具写**绝对路径**）
1. `notes.md`
   - 按研究问题分节：答案（1–3 句）→ 依据 → 不确定之处。
   - “来源”一节：编号列表，一手来源标 **PRIMARY**，每条一句“它证明了什么”。
   - “命令与输出”一节（如果有）：命令、关键输出、运行时间与环境。
   - “开放问题”一节：没回答的问题、矛盾、需要用户决定的事。
2. `ledger.md`：在已有模板的表格里填行（保留表头），格式见下。

完成后回复：你写入的文件绝对路径、每个研究问题的一句话答案、台账三种类型的行数、全部 speculative 论断、最重要的 3 个来源、资料里错误或过时的地方。
````

## 台账格式

`rh check` 要求：一张 Markdown 表格，表头包含“论断”“证据”“类型”三列（可多列，顺序不限）；每行证据不能为空或写“无 / TODO”；类型只能是 `observed` / `inferred` / `speculative`。

在 `rh new` 生成的模板上加一列“页面”，写稿时由主会话填写（论断出现在哪个面板或 finding）。下面的行只示范格式，内容是虚构的：

```markdown
| # | 论断 | 证据 | 类型 | 页面 |
|---|---|---|---|---|
| C1 | 平台 X 的 bonding curve 在市值达到阈值后迁移到 DEX | https://docs.x.example/graduation （“Graduation” 一节，访问于 2026-10-05） | observed | |
| C2 | 迁移阈值越低，狙击机器人的获利窗口越短 | 由 C1 与 notes.md §2 的链上样本推出 | inferred | |
| C3 | 下一代平台会把迁移改成链上拍卖 | 两个项目方路线图提到，未上线（notes.md 来源 7、9） | speculative | |
```

- **observed**：直接读到或测到，有一手证据（URL + 位置、`path:line@commit`、命令输出）。
- **inferred**：由台账里的 observed 行推出。证据写“由 Cx 推出”并说明推理。
- **speculative**：没有验证的判断。页面上必须写明是推测。
- 一行只放一个论断。证据太长时写到 `notes.md`，台账里写“notes.md §x”。
- 证据单元格里出现竖线 `|` 时写成 `\|`，或放进反引号。

## 多路并行

题目大（例如资料有几百 KB、研究问题跨好几个领域）时，拆成 2–4 路，每路一个 agent 同时跑：

- **按研究问题拆**，不要按资料拆。每路拿到 brief 里属于它的问题，以及读哪些资料的明确清单（agent 可能没有列目录的工具，给绝对路径）。
- 每路共用一份“通用说明”（输入、方法、台账格式），再加一份本路说明（要回答的问题、必读资料、外部核实重点）。把它们写成文件，任务里只给文件路径。
- 每路只写一个文件 `research/notes-<lane>.md`，台账表放在文件末尾，编号用本路前缀（例如 M / P / A），证据里的 `[n]` 指本文件“来源”一节。
- 全部完成后，由主会话收齐文件、把各路台账合并成 `ledger.md` 的**一张表**（`rh check` 只读第一张表），再写 `notes.md` 索引。见 SKILL.md §3 第 3 步。
